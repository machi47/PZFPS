# Visual issue ledger

This is the authoritative checklist for visual work reported during the live
first-person diagnostic. A passing unit/GPU fixture does not close an item. An
item becomes **accepted** only after a moving-view live check shows the intended
result without a regression in the neighboring cases.

The original screenshots are retained locally (not committed proprietary game
art) under `.local/captures/user-visual-reports/2026-09-17/`. The complete
machine-readable installed-asset audit is
`.local/reports/asset-coverage-pz-42.20.json`, generated by
`bin/pzfps assets audit-coverage`.

## Corpus coverage baseline

The installed indexes are now joined rather than treated as isolated files:

- 21,523 tile-geometry identities;
- 35,746 atlas texture identities;
- 32,284 tile-definition identities with gameplay/assembly properties;
- 39,902 unique joined definition/geometry/texture identities;
- 5,158 joined identities with at least one source primitive;
- 3,835 named model identities, of which 3,732 resolve a mesh and 3,442
  resolve a texture in the installed model index;
- 5,092 unique item-script identities from 5,105 installed declarations (13
  duplicate identities are preserved rather than hidden); 3,857 declare and
  resolve a world model, while 1,235 declare no world model.

Important category totals from the current audit:

| Category | Identities | Honest renderer state |
|---|---:|---|
| Roof | 4,569 | 3,949 compiled from installed depth atlases pending live acceptance; 84 authored-geometry identities unaccepted; 536 rejected/unsupported |
| Door | 166 | all rejected as non-volumetric |
| Window | 648 | all rejected as non-physical |
| Fence | 1,214 | four exact short-chain-link identities implemented but unaccepted; 1,210 unaccepted |
| Furniture/fixture | 1,512 | two exact dresser identities implemented but unaccepted; 584 lack a static geometry path |

This is a corpus of installed tile/sprite definitions, named models and item
scripts, not a claim that every runtime state combination is already known.
Runtime-created objects, mod content, character clothing combinations, damage,
open/closed state and multi-tile scene grouping are joined when they appear in a
captured scene. The audit describes representation coverage, not appearance
quality. A source
box can still be the wrong visible mesh, and a resolved native model can still
be placed, lit or animated incorrectly. Runtime Java type, orientation, object
state, multi-tile grouping and building topology must be joined before an asset
can be accepted.

The captured problem-house snapshot is also audited rather than inferred from
the global inventory:

```text
bin/pzfps assets audit-scene \
  --scene .local/reports/prop-boundary-scene.json \
  --output .local/reports/prop-boundary-scene-coverage.json
```

That scene contains 586 object instances across 189 exact identities, with zero
identities absent from the installed corpus. Its 91 roof instances all resolve
to the compiled or authored roof registry. This proves deterministic identity
coverage only; it does not prove that the reconstructed surfaces look correct
from a moving first-person camera.

## Roof reconstruction checkpoint

`bin/pzfps assets compile-roof-surfaces` reads PZ's installed
`tileDepthTextureAssignments.txt` and depth PNG atlases. It reconstructs points
using PZ's source projection/depth equations, accepts only connected planar
patches with at least 95% source-depth coverage, limits convex-hull fill to
1.15, and rejects non-finite, degenerate, out-of-bounds or source-projection
violations. Authored tile geometry has precedence over the supplemental
registry.

The current local output contains 3,998 supplemental identities and 38,372
triangles. Of those identities, 3,949 are roof-category identities; the
remainder are installed depth helpers used by the same deterministic path. The
compiler rejected 8 entries with no depth image, 76 that did not meet the
piecewise-planar constraint and 417 unsafe patch hulls. Java load/render tests
validate the generated registry in addition to the Python geometry audit.

The isolated launch on 17 September loaded the staged registry and ran at
59.91--60.08 completed callbacks/s with zero dropped mesh requests. However,
the attempted screenshot contained only the desktop, not a PZ window. That
attempt is recorded as **inconclusive**, and V-12 remains unaccepted.

## Checkpoint rule

Do not reopen the game merely because code compiled or a narrow synthetic probe
passed. A new live checkpoint must name which V-IDs it is intended to improve,
include a deterministic fixture for those IDs, pass automated topology/depth
checks, and leave unrelated rejected experiments out of the deployed JAR.
