# Visual issue ledger

This is the authoritative checklist for visual work reported during the live
first-person diagnostic. A passing unit/GPU fixture does not close an item. An
item becomes **accepted** only after a moving-view live check shows the intended
result without a regression in the neighboring cases.

The original screenshots are retained locally (not committed proprietary game
art) under `.local/captures/user-visual-reports/2026-09-17/`. The complete
machine-readable installed-asset audit is
`.local/reports/asset-coverage-pz-42.20.json`, generated by
`bin/pzfps assets audit-coverage`.

every installed `.lotheader` with the authoritative atlas index. Header
presence establishes that an installed map can request an identity; it is not
an object-instance count. The coverage report exposes map-reference status and
renderer state per identity, plus state totals by category. This separates
real installed-world holes from unused atlas slots without asking the owner to
rediscover them by eye.

## Furniture and fixture reconstruction checkpoint

`bin/pzfps assets compile-prop-surfaces` now evaluates every installed
furniture/lighting identity that has both a tile definition and atlas sprite.
It examined 1,556 candidates and accepted 988 identities: 840 furniture/fixture
and 148 lighting/attached-fixture identities. The accepted registry contains
177,709 exact mask rectangles expanded by Java to 355,418 triangles. Of the
1,513 furniture/lighting identities referenced by installed map headers, 981
now use this source-backed path (835 furniture and 146 lighting).

The compiler does not treat PZ's `tileGeometry` boxes as visible object meshes.
Those boxes often describe interaction/collision support and caused the open
dressers, malformed sinks and oversized switches in evidence 14, 23–24, 29–32.
Instead, each depth sample is intersected with the exact installed sprite alpha
mask, fitted to bounded planar patches, and decomposed into exact opaque-mask
rectangles. An identity is allowed to replace authored support geometry only
after at least 98% of its actual source pixels survive the final fit, every
patch stays within a conservative tile-local envelope, and all emitted
triangles are finite, nondegenerate and project back inside the source tile.

The other 568 candidates fail closed with recorded reasons: 259 are not safely
piecewise planar, 196 lack 98% source-mask depth coverage, 110 lose too much
source coverage during fitting and three have empty/tiny source art. The
reported examples `furniture_storage_01_12`, `furniture_storage_02_36`,
`furniture_bedding_01_52`, `fixtures_sinks_01_5`, `fixtures_sinks_01_9`,
`fixtures_counters_01_154` and `lighting_indoor_01_1` all pass. Their final
source coverage ranges from 98.136% to 100%; the exact result and rejection
reason for every identity are joined into
`.local/reports/asset-coverage-pz-42.20.json`.

The packaged live client subsequently loaded the authored registry plus both
the roof and prop supplemental registries and reported 9,812 resolved geometry
identities. Its GLFW window appeared only as an inaccessible off-screen
174x158 surface, so this is a successful live-load check, not visual
acceptance. The client was stopped after the bounded check. Its observed memory
footprint has no controlled pre-registry baseline, so no performance conclusion
is claimed from that launch.

This is persistent identity-level visible-surface reconstruction, not a claim
that a single isometric sprite reveals an object's unseen back, interior or
state variants. It should remove the unsupported box faces and oversized masks
systemically wherever the same identity is reused across houses. It does not
by itself solve multi-tile ownership, exterior-wall clipping, doors, windows,
fences, roofs, animation states or truly unknown reverse-side geometry. Those
remain separate ledger entries and live acceptance requirements.

## Roof reconstruction checkpoint

`bin/pzfps assets compile-roof-surfaces` reads PZ's installed
`tileDepthTextureAssignments.txt` and depth PNG atlases. It reconstructs points
using PZ's source projection/depth equations and accepts only connected planar
patches with at least 95% source-depth coverage. A patch whose convex hull would
bridge too much transparent source area is decomposed into vertically merged
scanline rectangles that exactly cover its alpha mask. Non-finite, degenerate,
out-of-bounds or source-projection violations still fail closed. Authored tile
geometry has precedence over the supplemental registry. Authored roof boxes are
closed volumes, but the renderer previously projected source texture onto only
the faces visible to PZ's original isometric camera. It now mirrors the matching
observed face in local box space onto every complementary X/Y/Z face. The
installed corpus contains 74 such roof-box identities, 71 referenced by map
headers (4,548 header references); the retained live scene contains 84 instances
across 28 of those identities. The renderer reports the number of generated
faces as `completedRoofBoxFaces`. This is deterministic offline coverage, not a
live visual acceptance or a solution for non-box roof planes and junctions. A
bounded 2026-09-23 isolated launch loaded the registry without renderer errors
but remained in PZ's startup/Bink state for more than five minutes, so it was
stopped without promoting V-12's acceptance state.

The current local output contains 4,413 unconditional supplemental identities
and 88,473 primitives (88,463 depth-derived triangles plus ten inherited
source-authored boxes). Of those identities, 4,331 are roof-category identities; the
remainder are installed depth helpers used by the same deterministic path. Of
the emitted identities, 414 use exact alpha-mask rectangle decomposition (21,810
rectangles). Seventy-two compound roof identities that narrowly missed the
strict 0.018 inlier threshold now use an auditable 0.025 quantisation retry.
Every accepted patch still passes the existing 95% source-depth coverage rule
and 0.012 maximum RMS gate; the measured corpus maximum is 0.0116119.

Four installed-map-referenced `walls_exterior_roofs_30_21` identities are
atlas-only even though their matching `walls_exterior_roofs_30_19` identities
have definitions and compiled surfaces. The compiler now checks the actual
installed atlas pixels before inheriting: each destination mask must be a
strict subset of its same-suffix source, may add zero opaque pixels, may remove
at most one tile-width of border pixels, and must retain at least 90% of the
source mask. The four accepted identities remove 90--91 border pixels and
retain 92.86--97.46%; the evidence and source identity are recorded per asset.
This is an offline deterministic recovery, not yet a live visual acceptance.

The compiler still rejects the canonical `roofs_30_01_90` depth fit because it
exceeds the conservative tile-local envelope. Ten same-suffix material variants
instead inherit its installed authored box after the compiler verifies the
explicit depth assignment, identical original-frame placement and an atlas
alpha subset retaining 86.78--100% of the source. Twenty-four
`roofs_accents_30_01` variants inherit cardinal anchoring only from their
explicitly assigned `roofs_accents_01` target; seven diagonal accent identities
use their own installed `attachedNW`/`attachedSE` properties. Each accepted
alias records its source and evidence. Of the remaining entries without direct
physical anchoring semantics, 80
now have a separate contextual surface backed by an exact neighbor relation in
PZ's installed `seams.txt`; runtime emits those surfaces only if the immutable
snapshot contains one of the declared neighboring canonical roof identities.
Only one compiler identity remains rejected as an unanchored overlay. Eight
former `missing_depth_image` entries are separately classified as source

## Checkpoint rule

Do not reopen the game merely because code compiled or a narrow synthetic probe
passed. A new live checkpoint must name which V-IDs it is intended to improve,
include a deterministic fixture for those IDs, pass automated topology/depth
checks, and leave unrelated rejected experiments out of the deployed JAR.
