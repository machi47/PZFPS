# Implementation constraints

Preserve the actual PZ client as gameplay/network/animation authority. This package owns canonical visual assets and normalized presentation state, not a second simulation. Do not add a Workshop subscription, screen-overlay baseline, OS upgrade, proprietary DLL, or mandatory model download as a gate.

Develop and run code; do not replace an implementation request with another handoff prompt. Commit meaningful tested changes and verify the remote. Never overwrite unpublished local work or force-push history. Keep game assets, extracted/decompiled sources, weights, caches, and large captures under the root workspace's .local/ and out of Git.

Do not prescribe Godot or another renderer as best without measurements. This package's GLB/state contracts are independent of that choice. CPU fixtures are not gameplay. Learned completion is not validated without an actual model run. Do not claim missing surfaces are observed, painted RGB is recovered reflectance, or a stable but wrong asset is artifact-free.

Prefer existing mesh/model/numerical packages. Add integrations against verified interfaces. Fix actual failures and retain regression tests rather than growing prerequisite checklists.
